# Hash-pinned lock files (requirements-dev.lock)

## What it is

A **lock file** lists every package the project needs, at one exact version, including the packages those packages
need (the **transitive** dependencies). A **hash-pinned** lock file also gives, for each package, the fingerprint
(a SHA-256 hash, a 64-character number computed from the file's bytes) of every file that may be installed. If a
downloaded file does not match, pip refuses it.

## Why this repository uses it

The checks in this repository (ruff, mypy, the tests) must behave the same on a laptop, in CI and in a fresh clone
a year from now. Exact versions give that. The hashes add a second guarantee: a package that was replaced or
tampered with on the index is not installed.

## Where it appears

| File | What it does with this technology |
| --- | --- |
| `requirements-dev.lock` | 51 pinned packages with hashes: the test, lint and audit tools, the runtime packages and everything they need. |
| `requirements.lock` | 8 pinned packages with hashes: Flask, gunicorn and what they need. The Dockerfile installs this file. |
| `pyproject.toml` | `[project.optional-dependencies] dev = [...]` lists the loose ranges the lock file was made from. |
| `Makefile` | `pip install --require-hashes -r requirements-dev.lock`; the stamp rule reruns when the file changes. |
| `make audit` | Scans the lock file for known vulnerabilities. |

## How it works underneath

1. A developer writes loose rules in `pyproject.toml`: for example `pytest>=8,<10` ("version 8 or 9").
2. A **resolver** (here, the tool `uv`) picks one version for each rule and for every package those need, so that
   all rules hold together. It records the result: `name==version`.
3. For each version, it records the hashes of the files published on PyPI (one per platform or Python version).
4. `pip install --require-hashes -r file` downloads only those exact versions and verifies each file's hash before
   unpacking. Any mismatch stops the install.
5. The lines `colorama==0.4.6 ; sys_platform == 'win32'` carry an **environment marker**: install this package only
   on Windows. `--universal` made the lock work on every platform.

## Walkthrough of this repository's use

`requirements-dev.lock`:

```text
# This file was autogenerated by uv via the following command:
#    uv pip compile pyproject.toml --extra dev --universal --generate-hashes --python-version 3.12 -o requirements-dev.lock
```

The two comment lines (they begin with `#`) record how the file was made: `uv pip compile` read `pyproject.toml`,
included the `dev` extra, made a platform-independent result (`--universal`), added hashes (`--generate-hashes`),
for Python 3.12 as the lowest version (`--python-version 3.12`), and wrote the result to `requirements-dev.lock`.
`uv` is a fast Python package manager; this repository uses it only to produce the file, never to install.

`requirements-dev.lock`:

```text
pytest-cov==7.1.0 \
    --hash=sha256:30674f2b5f6351aa09702a9c8c364f6a01c27aae0c1366ae8016160d1efc56b2 \
    --hash=sha256:a0461110b7865f9a271aa1b51e516c9a95de9d696734a2f71e3e78f46e1d4678
    # via lockpci (pyproject.toml)
```

- `pytest-cov==7.1.0` is the exact version.
- Each `--hash=sha256:...` line is one acceptable file (for example the wheel and the source archive). The trailing
  `\` joins the lines into one requirement.
- `# via lockbase (pyproject.toml)` says who asked for it. The word `lockbase` is the name of the scratch project the
  file was compiled from: it had the same `dev` list as this repository. The comment is a record, not a dependency.

`requirements-dev.lock`:

```text
certifi==2026.10.23 \
    --hash=sha256:a9895e6e2758b371e0545e321a3a8fd1fcfd9829ada8824a936dfb16aaaf36cd \
    --hash=sha256:e9b54de76e530bb6cf0ccd036787103acb58fd42ba930ea8bf948ddbaa2f61d1
    # via requests
```

Here `# via requests` says this package is wanted only because `requests` needs it. `requests` itself is wanted by
`pip-audit`. That chain is a transitive dependency.

`requirements-dev.lock`:

```text
colorama==0.4.6 ; sys_platform == 'win32' \
```

The marker after `;` means: only on Windows. On macOS and Linux pip skips the line.

## Try it yourself

```bash
grep -cE '^[A-Za-z0-9_.-]+(\[.*\])?==' requirements-dev.lock
```
Prints `51`: the number of pinned packages.

```bash
grep -A3 '^pytest==' requirements-dev.lock | cut -c1-80
```
Shows the pinned version and the first hash lines.

```bash
.venv/bin/pip install --require-hashes --dry-run -r requirements-dev.lock | tail -2
```
Everything is already installed, so pip reports that the requirements are satisfied.

```bash
printf 'idna==3.10\n' > /tmp/unpinned.txt && .venv/bin/pip install --require-hashes --dry-run -r /tmp/unpinned.txt
```
pip stops with an error that the requirement has no hash. That is the protection at work.

```bash
make audit
```
Needs network access. Expect two `WARNING` lines (pip-audit suggests fully hashed pins) and then `No known vulnerabilities found`.

## Mistakes people make

- **Editing the lock file by hand.** Change `pyproject.toml` and regenerate with the `uv pip compile` command shown in
  the file's header.
- **Pinning only top-level packages.** Their dependencies could change underneath. A lock file pins all of them.
- **Updating without re-checking.** A new lock file can bring new versions; the tests and `make audit` must run
  again.
- **Assuming the lock covers the build backend.** `setuptools` is fetched while the project is installed and is not
  in this file. See `setuptools.md`.

## Check yourself

1. What is the difference between `pytest>=8,<10` and `pytest==9.1.1`?
   **Answer:** The first is a range of acceptable versions; the second is one exact version. The first lives in `pyproject.toml`, the second in the lock file.
2. What does a hash protect against that a version number does not?
   **Answer:** A file that has the right version number but different bytes, for example a tampered or replaced upload.
3. Why is `requirements.lock` almost empty?
   **Answer:** The program has no runtime dependencies; it uses only the standard library.
4. What does `# via requests` mean?
   **Answer:** The package is in the lock file because `requests` needs it, not because the project asked for it directly.
5. Which tool made the file, and which tool installs from it?
   **Answer:** `uv pip compile` made it; `pip install --require-hashes -r` installs from it.
